## 1.bis — Icono de la pantalla del PIN: mano → huella dactilar

**Objetivo:** En la pantalla del código secreto (PIN), el botón de biometría usa el emoji 🤙 (mano "call me"), que no comunica "huella". Cambiarlo por un icono de **huella dactilar** (o similar).

**Ancla de código:**
- Botón: `#pinBioBtn` en [buddy/www/index.html:2432](../../../buddy/www/index.html) — actualmente `>🤙<` (`<button class="pin-key" data-val="bio" id="pinBioBtn" style="font-size:1.4rem">🤙</button>`).
- Lógica que lo muestra/oculta: `updatePinScreen`/`biometricAvailable` (~`4790-4795`) y `tryBiometric()` — **no tocar**, solo el glifo.
- Referencias en la FAQ (texto "bouton/button/botón 🤙") en los 3 idiomas: ~`3726` (FR), `3752` (EN), `3778` (ES) — actualizar el emoji ahí también para coherencia.

**Decisión:** el emoji de huella 🫆 (Unicode 16) **puede no renderizar** en el WebView de Android del dispositivo. Más seguro: un **SVG inline** de huella (como el patrón del icono fuente) o un glifo ampliamente soportado (p. ej. 👆 / 🔒 no son "huella"). Recomendado: SVG inline pequeño dentro del `<button>` para garantizar el render. Verificar en el Xiaomi (CDP) que se ve.

**Esfuerzo:** trivial (1 botón + 3 strings FAQ), pero requiere decidir el glifo/SVG y verificar render en dispositivo.

## 4. Publicar release v3.3 (cierra el ciclo de distribución)

**Prerrequisito de seguridad:** keystore en `buddy/android/app/keystore.properties` + `buddy/zova-release-keystore.jks` — **JAMÁS committear** (ya en .gitignore; verificar).

**Pasos:**
1. Subir `versionCode` (v2.1 = versionCode 3 → siguiente 4) y `versionName` a `3.3` en `buddy/android/app/build.gradle`.
2. `npx cap sync android` → `cd android` → `.\gradlew assembleRelease` (firma v2 con la keystore).
3. APK firmado → `buddy/Zova-v3.3.apk`.
4. GitHub Release con el APK adjunto; regenerar QR (`buddy/assets/qr-download.png`) apuntando a la descarga directa de v3.3.
5. Actualizar la landing (bloque 1.2) con el enlace real.
6. `git push` (solo cuando el usuario lo pida).

⚠️ Recordatorio: debug y release tienen firmas distintas → instalar el release sobre un debug existente requiere `adb uninstall` (se pierden datos). Avisar al usuario antes.
