# Fase C — Endurecimiento del Wizard (2.4 / 2.5 / 2.6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Endurecer el wizard de personas: zona de rescate con reintento de generación sin perder respuestas (2.4), garantizar el idioma nativo del greeting (2.5) y limpiar el ciclo de vida de navegación del `backButton` (2.6).

**Architecture:** Todo en `buddy/www/index.html`. (2.4) Se guarda un `currentWizardDraft` al lanzar la generación; el path de fallback manual muestra el `#wizardBanner` con un botón "↻ Réessayer la génération auto" que reabre el wizard restaurando las respuestas (`openPersonaWizard(draft)`). (2.5) Se añade una directriz explícita de idioma al meta-prompt del wizard. (2.6) `closePersonaWizard()` resetea `wizardStep`; el listener `backButton` único ya delega correctamente (no se duplica ni se elimina — es el patrón correcto).

**Tech Stack:** HTML single-file + Capacitor, `chatCompletion()`, listener `App.backButton` único. Sin build de JS — sync con `npx cap sync android`.

**Verificación (sin test runner):** preview `zova-preview`. Funciones en closure → verificar por (a) consola sin errores tras recargar, (b) app renderiza, (c) DOM (banner/botón de rescate, restauración de campos del wizard). Para 2.4 se simula el fallo de red poniendo una clave inválida única. Dispositivo solo para E2E final.
